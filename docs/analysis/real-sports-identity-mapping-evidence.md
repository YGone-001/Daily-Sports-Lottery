# 真实体育数据身份与映射证据审计

本文件记录一次**只读**的真实数据审计：用仓库中已存在的真实体育数据，测量现有源身份与 Canonical
映射实现的**实际可测效果**，并明确区分「测到的」「推导的」「推断的」「测不到的」。

> 本文件不授权任何运行时激活，也不建议任何生产改写。审计结束时的立场是
> `PRODUCTION_ACTIVATION_READY = NO`、`DECISION = NO-GO`。

复现命令（只读，不写任何受保护存储）：

```bash
python -m tools.real_sports_identity_audit --summary
python -m tools.real_sports_identity_audit --output <仓库之外的路径>/audit.json
python -m pytest -q tests/test_real_sports_identity_audit.py
```

## 1. 目的与边界

审计回答一个问题：**现有身份与映射实现，在真实数据上到底能自动做对多少、会漏多少、需要人工
补多少？**

边界（由工具强制，不是文档承诺）：

| 约束 | 实现方式 |
| --- | --- |
| 只读 | 七个受保护存储只以 `open(..., "r")` 打开；审计前后各算一次 SHA-256，不一致即中止 |
| 无网络 | 工具只依赖本地 JSON 与 `hashlib`；源码中不存在 `socket` / `requests` / `urllib` / `http.client` |
| 无生产写入 | 报告输出路径先经 `assert_safe_path()`，仓库与生产根一律拒绝 |
| 可复现 | 所有集合按 Canonical ID 或身份键字符串排序；两次运行除 `latency` 外逐字节一致 |
| fail-closed | 结构不可能的输入抛 `AuditInputError`，不修复、不猜测、不降级 |

未执行的操作：未调用 `scraper.refresh()`，未下载实时数据，未重算任何结算，未修改模型概率，
未改写任何 Canonical ID，未执行生产修复的 `apply` / `recover`。

## 2. 方法与证据分级

审计复用既有实现，不复制判定逻辑：

| 复用对象 | 用途 |
| --- | --- |
| `utils.source_identity.observe_source_row` | 把每条真实 Canonical 记录转成不可变 `SourceObservation` |
| `utils.source_identity.ScopedSourceIdentityKey` | 判定该记录的身份证据是否**足以授权活动绑定** |
| `utils.source_identity.detect_all_conflicts` | 只读冲突分类（跨运动、行位置复用、强编号、Canonical 归属） |
| `utils.ingestion_identity.plan_ingestion_identity` | 以「同集合重放」检验批次可归属性与幂等性 |
| `utils.match_identity.same_event` | **被审计的候选生成器**（不作地面真值） |
| `utils.source_id_migration.enumerate_store_references` | 七存储引用枚举 |
| `utils.settlements.outcome_from_score` / `result_fingerprint` | 结算与赛果的一致性核对（只读比对） |

**证据分级**（报告中每一处结论都带标签）：

| 标签 | 含义 |
| --- | --- |
| `OBSERVED` | 直接从受保护存储读出 |
| `DERIVED` | 由既有实现或本审计显式规则计算得出 |
| `INFERRED` | 外推、适配器归属推断或工作量估计 |
| `UNKNOWN` | 现有证据无法测量 |

### 2.1 代理标签协议（关键限制）

仓库中**不存在**任何独立人工复核的等价标签。因此本审计定义了一个**字段证据代理**
`classify_pair_evidence`，并与 `same_event()` 刻意不同：

- 它**不**把「竞彩编号相同」当作等价规则；
- 它要求队名精确或仅空白/标点差异；
- 把截断队名、开赛时间冲突、联赛冲突、编号冲突、赛果冲突一律降级为 `AMBIGUOUS`；
- 只有决定性矛盾才判 `DIFFERENT_EVENT`。

代理标签的用途**仅限于描述「候选生成器与独立字段证据的一致/不一致」**。它不是精度，
不是召回，也不是人工结论。凡需要人工标签的指标，本报告一律记 `N/A`。

## 4. 源身份稳定性分析

### 4.1 身份充分性

| 分类 | 数量 | 含义 |
| --- | ---: | --- |
| `COMPETITION_NUMBER`（充分） | 489 | 带 `(sport, date, 编号)` 三重作用域 |
| `INSUFFICIENT`（不充分） | 37 | 只有 provider 推导出的数字尾巴，永不授权活动绑定 |
| `RAW_PROVIDER_ID` / `UNVERIFIED_PROVIDER_ID` | 0 | 记录中未保留任何 provider 标识符 |

37 条不充分记录全部形如 `500l-<date>-<provider_number>`（例：`500l-2026-10-07-1398620`），
其数字尾巴既不是竞彩编号，也无法从字段证明其唯一性作用域。

另有 1 条记录（`DERIVED_FROM_PROVIDER_FIELDS` 共 38 条，不充分 37 条）从 `odds.matchnum`
补到了编号，因此稳定性分类与充分性分类相差 1 条——这是**同一套既有实现内部的口径差**，不是数据错误。

### 4.2 跨运动命名空间

`500j-` 前缀在真实数据中同时承载足球（23 条）与篮球（100 条）。本次数据中**没有出现同一条
`500j-<date>-<n>` 字符串同时属于两个运动**（`(date, 数字)` 交集为 0），因此
`CROSS_SPORT_SHARED_NAMESPACE` 冲突计数为 0：风险是真实的（共享前缀），但在本批次未触发。

同时确认：足球与篮球使用同一数字（如都为 `301`）时，作用域身份键不同
（`football|date|jczq|301` vs `basketball|date|jczq|301`），不会被合并。

### 4.3 冲突检测器的口径问题（实测发现）

真实数据上 `detect_all_conflicts` 报出 **52 条 `STRONG_NUMBER_CONFLICT`（严重度 `REJECT`）**。
逐条核对后，**全部 52 条都不是真实的身份冲突**：检测器以
`SourceObservation.stability_scope`（adapter × sport × date × namespace × raw_type）分组，
而该 scope 是**域**而非**身份**。于是同一天同命名空间下的多场不同比赛（各自编号不同）被当成
「同一源身份携带互斥编号」。

| 例 | 分组键 | 被误判为冲突的编号 |
| --- | --- | --- |
| 1 | `live_basketball|basketball|2026-10-01|500lq|COMPETITION_NUMBER` | 303、304 |
| 2 | `live_basketball|basketball|2026-10-09|500lq|COMPETITION_NUMBER` | 301、302、303、304、305 |
| 3 | `live_basketball|basketball|2026-10-10|500lq|COMPETITION_NUMBER` | 302、304、306 |

而按 `derived_source_id`（真正的源身份）分组时，**不存在任何**强编号互斥。也就是说：
**52 条 REJECT 级告警在本数据上是 100% 噪音**，若未来直接用于阻断决策会造成大面积误阻断。

### 4.4 行位置派生标识符的实际腐蚀（实测）

`calibrated.json` 的 520 个 ID 中有 **387 个已不在当前 Canonical 集合**（74.4%），
其中 **386 个是 `500w-`（完场 feed 行序号）**，例如 `500w-2026-09-29-0`、`500w-2026-09-29-97`。
另有 1 个 `500lq-2026-10-01-周三302`（带中文星期前缀的历史格式）。

> 这是「行位置派生 ID 跨刷新不稳定」最直接的实测证据：同一 feed 重跑后，旧 ID 无法再被任何
> 记录复现，历史引用只能悬挂。校准存储保留这些历史 ID 可能是**有意的追加式留档**，本审计不判定
> 其为错误，但明确指出：**任何以下游引用行位置 ID 为前提的链路都无法自我复现。**

### 5.3 截断队名导致的 22 组候选重复（不确认）

22 对全部具备以下画像（`ambiguous_pair_profile`）：

| 特征 | 计数 |

逐条定义与局限：

1. **身份完整率**——身份键足以授权活动绑定（`COMPETITION_NUMBER` 或已验证 `RAW_PROVIDER_ID`）。
   局限：记录中无任何 provider 原始标识符，该证据通道结构性不可用。
2. **重复源身份键率**——同一充分身份键被 ≥2 个 Canonical ID 占用。局限：键共享只是冲突信号，
   不等于映射错误。
3. **Canonical 冲突率**——按字段证据共享同一真实赛事的 Canonical ID 比例。局限：属推导结论，
   需人工裁定。
4. **自动映射覆盖率**——同集合重放时，规划器把每条记录映射回自身 ID 的比例。局限：**原始重放
   结果是 `BLOCKED`**，分子取自「移除 2 条冲突记录后」的重放，是上界而非当前线上能力。
5–6. **精度 / 召回**——无人工标签，不可计算。
7. **代理误合并率**——`same_event()` 判同而字段证据矛盾/降级的对，占算法正例。局限：代理标签，
   不是精度。
8. **代理漏合并率**——字段证据判同而 `same_event()` 判否的对，占证据正例。局限：同上。
9. **代理降级候选对比例**——22 对中「开赛时间一致」者比例，用于刻画截断命名的系统性。
10. **歧义事件复核率**——卷入歧义对的 Canonical 事件比例。局限：复核队列，不是错误清单。
11. **证据不足率**——身份键不充分的比例；这些记录 fail-closed，只能复核。
12. **预测快照链接率**——至少有一个可解析预测快照的事件比例。局限：缺失也可能只是生命周期
    尚未到达该阶段。
13. **赔率快照链接率**——分母排除无赔率块的 37 条事件（其不可能有赔率快照）。
14. **赛果链接率**——`status=finished` 且持有合法全场比分的事件比例。缺 17 条。
15. **结算链接一致率**——快照可解析、`match_id` 一致、`actual_outcome` 与比分一致、
    `result_fingerprint` 可复算的结算比例。局限：只做一致性核对，未重算结算公式。
16. **评估样本链接一致率**——快照与结算均可解析、比赛/赛果/模型版本一致的比例。
17. **处理延迟**——本机单次墙钟时间（见第 10 节）。局限：机器相关、不含 I/O。
18. **估计人工复核量**——重复归属、歧义、证据不足、完赛无赛果的**去重记录数**。局限：只数条目，
    不折算工时或成本。
19. **标识符不稳定率**——标识符为行位置派生 / provider 推导 / 未知的事件比例。

## 13. 后续更正记录：强编号冲突的分组口径

> 本节记录对本报告第 4.3 节结论的**后续更正**。第 4.3 节与第 7 节中的
> 「52 条 `STRONG_NUMBER_CONFLICT`」是更正前在 `a1392e5` 上的**真实测量结果**，
> 作为历史记录保留，不作改写。

**缺陷**：`detect_strong_number_conflict` 以 `stability_scope.as_key()`
（adapter × sport × event_date × namespace × raw_identifier_type）分组，而该键描述的是
**源域**而非**源事件身份**；同一域内的多场独立比赛因此被误判为「同一身份携带互斥编号」。
同一口径下还存在**反向漏检**：`raw_identifier_type` 取决于「id 尾段是否恰等于竞彩编号」，
会把同一个源 ID 的两条观测拆进不同的域。

**更正**：分组键改为 `strong_number_identity_key()` =
`(adapter, sport, event_date, derived_source_id)`；`derived_source_id` 缺失时返回 `None`。
严重度契约不变（真实矛盾仍为 `REJECT`，治理目标仍为 `REJECTED`）。

**同一未改动输入上的前后对比**（`data/daily_matches.json` SHA-256
`1d71473ca5b1934693482d4d888df617d0348970ff1f1041b7ff2803b62b0751`，526 事件、526 观测）：

| 项 | 更正前 | 更正后 |
| --- | ---: | ---: |
| `STRONG_NUMBER_CONFLICT` | 52 | **0** |
| 其他三类冲突（跨运动 / 行位置 / 归属） | 0 / 0 / 0 | 0 / 0 / 0 |
| 冲突总数 | 52 | 0 |
| 真实身份矛盾残留 | — | 0（本数据确无逐身份矛盾） |

被消除的 52 条全部是**域级**告警：每条告警覆盖 2～31 条不同的源身份
（成员数直方图：2×5、3×3、4×5、5×5、6×4、7×3、8×5、9×5、10×3、11×3、14×4、15/20/22/23/27/28/31 各 1），
其中**没有任何一条**存在单条身份内的互斥编号。因此消除的原因是**分组不再把不同身份
