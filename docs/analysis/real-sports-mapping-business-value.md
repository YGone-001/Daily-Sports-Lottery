# 真实体育映射的业务价值评估

本文件把 `docs/analysis/real-sports-identity-mapping-evidence.md` 的实测证据，折算成**业务价值判断**，
并严格区分「观测到的收益」「估计的收益」「未被证明的收益」。

> 结论：现有实现**在等价性判定上是可信的、在覆盖面是不完整的**。真实数据中可以直接指出
> 2 组确定的重复 Canonical 归属与 22 组高度可疑的截断重复，且规划器在本数据上**整体 fail-closed**。
> 因此本轮不构成生产激活依据：`PRODUCTION_ACTIVATION_READY = NO`、`DECISION = NO-GO`。

---

## 1. 一句话结论

现有身份模型（`(sport, date, 竞彩编号)` 作用域 + 唯一性校验）在**有编号的记录上表现干净**
（489 条中 0 条重复键、0 条跨运动碰撞、0 条下游错指），但在**缺编号或被截断命名的记录上会
产生真实重复归属**（2 组确定 + 22 组疑似），并让整个批次的规划 fail-closed。
业务价值判断：**防护有效，覆盖不足，需要先修口径再加覆盖面，暂不可激活。**

---

## 2. OBSERVED_BENEFIT（实测到、可复核的收益）

| 收益 | 证据 | 规模 |
| --- | --- | --- |
| 编号作用域唯一性在真实数据上成立 | `duplicate_source_key_rate = 0/489` | 489 条有编号记录零冲突 |
| 运动隔离有效 | 足球/篮球同数字（301 等）不碰撞 | 170 条篮球 + 356 条足球 |
| 跨运动共享前缀未造成误合并 | `500j-` 同时承载两运动，同串碰撞 0 | 123 条 `500j` 记录 |
| **冲突在进入下游使用前被拦住** | 同集合重放 `BLOCKED`（`AMBIGUOUS_CANONICAL_OWNERSHIP`） | 1 次整体阻断，涉及 2 条记录 |
| 下游链接键可靠 | 孤儿引用 0；结算/评估一致率 94/94 | 1 125 条下游记录全部可解析 |
| 事件级自动绑定能力高 | 冲突消解后重放 `OK`，524/526 幂等一致 | 99.62% |
| 身份判定开销可忽略 | 43.7 µs/事件（22.98 ms / 526 事件） | 计算不是瓶颈 |

**关键的一条**：`plan_ingestion_identity` 在真实数据上**不是"跑通"，而是拦下**。审计把它记为收益，
因为拦下的正是「同一真实赛事被当成两个事件」这一类问题——这正是下游快照/结算最怕的错误类型。

## 3. ESTIMATED_BENEFIT（估计收益，标注推断）

| 估计项 | 数值 | 依据与置信度 |
| --- | --- | --- |
| 需人工确认的记录 | 78 / 526（14.8%） | 队列条目去重计数；**中等置信**（只数条目，不折算工时） |
| 若 22 组截断对确为同一赛事，可消除的重复归属 | 44 条记录（8.4%） | 22 对 × 2；**低-中置信**（无第三方源佐证） |
| 冲突前置发现 | 2 组确定 + 22 组疑似 | 高于「事后发现」；**中等置信** |
| 单批次额外处理开销 | ≈ 23 ms / 526 事件 | 本机墙钟；**高置信**（数量级稳妥） |
| 运营复杂度 | 1 个复核队列 / 4 类条目 | 重复归属、歧义、证据不足、完赛无赛果；**中等置信** |

> 说明：以上均为**条目数与耗时**，不含任何货币折算，也不含"减少多少人工成本"的推断。

### 3.1 只读提议工作流 vs 现有行为的对比

| 维度 | 现有行为 | 只读提议工作流 | 差异 |
| --- | --- | --- | --- |
| 可安全自动绑定 | 489 条有强编号记录 | 489 条（同） | 无差异 |
| 被整体阻断 | 是（1 次，2 条记录致因） | 否（按条进入候选/复核） | **提议流不阻塞整批** |
| 人工复核 | 无显式队列 | 78 条 × 4 类 | 新增可见工作量 |
| 冲突可见性 | 只在规划器抛出时可见 | 每批次确定性输出 | **显著提升** |
| 下游记录需排查 | 未知 | 92 条队名非精确（非错误） | 新增可见口径 |
| 处理开销 | 8.63 ms 规划 | +5.71 ms 两两比较 + 复核排队 | **+约 14 ms/批** |

结论：提议工作流用**约 14 毫秒/批**的额外开销换取「冲突可见 + 不阻塞整批」，
在当前数据规模下代价可以忽略；真正成本是 78 条人工裁定。

## 5. 与 Shadow 安全链的比例性

现有 Shadow 控制链包含 Ed25519 所有者签名、哈希链账本、批准版本/用途约束、重放防护、
七存储字节不变、隔离路径约束等。

| 观察到的风险 | 规模（真实数据） |
| --- | --- |
| 确定的重复 Canonical 归属 | 2 组（4 条记录） |
| 疑似重复（截断命名） | 22 组（44 条记录） |
| 跨运动命名空间碰撞 | 0 |
| 行位置标识符被复用 | 本批次 0（历史 386 条陈旧引用） |
| 下游错指（结算/评估指错比赛） | 0 |
| 冲突检测器假告警 | 52 条 |

**评估**：

- 对「**自动写入**」这一动作，现有链是**相称甚至偏保守**的：一旦允许自动写入，2 组确定的重复
  归属会被立即固化，且由于 `snapshot_id` 由 `match_id` 派生，改写后无法回滚复现——这正是强授权
  链存在的理由。
- 对「**只读分析**」这一用途，现有链**明显过重**：本次审计 43.7 µs/事件即可得出全部结论，却需要
  整套签名/账本链路才能落地一个报告。
- 因此建议**按用途分层**（只读分析 / 隔离影子写入 / 生产写入），而不是整体削弱任何一层。
  既有安全测试与 `assert_safe_path` 等不变量**不得**被放宽。

## 6. 优先改进项（按业务影响排序）

| 优先级 | 改进 | 实测依据 | 风险 |
| ---: | --- | --- | --- |
| 1 | 修正 `detect_strong_number_conflict` 的分组口径（应按 `derived_source_id`，而非 `stability_scope`） | 真实数据 52 条 `REJECT` 全部为假告警 | 若不修，任何「以冲突阻断」的策略会把 10% 的批次误判 |
| 2 | 缺编号记录（37 条）不得与有编号记录争抢 Canonical 身份：应挂起为候选，或仅在编号侧建立 Canonical | 2 组确定重复 + 22 组疑似重复的**共同结构性成因** | 直接决定重复归属率能否从 0.76% 降到接近 0 |
| 3 | 建立 provider 级**别名表**（数据驱动、可审计），而不是代码内启发式 | 下游 21/21/3 条缩写 + 21/25/1 条别名差异；`贝蒂斯` 是后缀，前缀启发式无效 | 别名表本身会成为新的身份风险面，必须版本化 + 人工确认 |
| 4 | 明确 `calibrated.json` 历史 ID 的引用语义（活跃 vs 留档） | 387/520 陈旧，其中 386 条为 `500w-` 行位置 ID | 下游若按 ID 反查会静默取不到数据 |
| 5 | 统一快照/结算/评估的队名写入口径 | 结算与评估沿用快照别名，形成第二套名字体系 | 跨存储重关联会被别名割裂 |
| 6 | 建立最小人工复核标签集（≥50 组，覆盖截断/别名/同队双赛） | 精度与召回目前 `N/A`，无标签则永远无法验收 | 未建立前，任何「高精度」说法都不成立 |

> 第 1 项是**缺陷修正**（不是放宽安全），第 2–6 项是**覆盖面建设**。
> 二者都必须带既有回归测试，且不得削弱 fail-closed 语义。
